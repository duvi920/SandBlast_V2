## 1. 레거시 코드 제거

### 1-1. 삭제 대상 파일 (5개)

ECS 전환 완료 후에도 남아 있는 MonoBehaviour 기반 구버전 코드.

| 파일 | 이유 |
|------|------|
| `Core/PlayerController.cs` | `[Obsolete]` 표시, ECS 이동 시스템으로 완전 대체됨 |
| `Core/PixelSimulator.cs` | ECS Job 파이프라인으로 대체됨 |
| `Core/ChunkManager.cs` | `ChunkManagerSingleton`으로 대체됨 |
| `Core/PixelGrid.cs` | `PixelGridSingleton`으로 대체됨 |
| `Core/ForceAccumulator.cs` | RigidBody ECS 시스템으로 대체됨 |

**작업 순서:**
1. `grep -r "PlayerController\|PixelSimulator\|ChunkManager\|PixelGrid\|ForceAccumulator"` 로 외부 참조 전체 확인
2. 참조 없으면 파일 + `.meta` 삭제
3. 남은 참조는 ECS 대응 API로 교체 후 삭제

## 2. 성능 최적화

### 2-1. 픽셀 동기화 Dirty Flag 도입

**현재 문제:** `PixelGridSyncSystem`이 매 5틱마다 전체 청크를 순회해 변경 감지 → O(청크 수) 비용 고정.

**개선안:** 셀을 수정하는 모든 경로에서 청크를 dirty로 마킹, SyncSystem은 dirty 청크만 처리.

```csharp
// ChunkManagerSingleton에 추가
public NativeHashSet<int> DirtyChunkIndices;

// PixelGridAPI / Job에서 셀 기록 시 호출
ChunkManager.MarkDirty(chunkIndex);

// PixelGridSyncSystem
foreach (var idx in DirtyChunkIndices) { /* diff 수집 */ }
DirtyChunkIndices.Clear();
```

**예상 효과:** 정적 맵(변화 없는 구간)에서 동기화 CPU 비용 90% 이상 절감.

**주의:** Job 내에서 `NativeHashSet`에 병렬 쓰기 시 `[NativeDisableParallelForRestriction]` 또는 `NativeQueue`로 수집 후 합산.

---

### 2-2. PixelImpactUtility 하드코드 제거

**현재 문제:** 파괴 가능 셀 목록이 `PixelImpactUtility` 내부에 직접 나열되어 있음.

**개선안:** `CellType.cs`의 `CellTypeExt` 분류 메서드를 단일 진실 공급원으로 사용.

```csharp
// Before (PixelImpactUtility 내 하드코드)
if (type == CellType.SOLID_DIRT || type == CellType.SOLID_WOOD || ...)

// After
if (CellTypeExt.IsDestructible(type))

// CellType.cs에 추가
public static bool IsDestructible(this CellType t) =>
    t is SOLID_DIRT or SOLID_WOOD or SOLID_GUNPOWDER or LIQUID_WATER or ...;
```

### 2-3. TeamRespawnSystem 즉시 부활 문제

**현재 문제:** 팀원 사망 즉시 부활 → 사망 패널티 없음.

**개선안:** `RespawnTimer` 필드 추가, 3초 딜레이 후 부활.

```csharp
// 컴포넌트에 추가
public float RespawnTimer;

// TeamRespawnSystem
if (state.IsDead && state.RespawnCount > 0)
{
    state.RespawnTimer -= SystemAPI.Time.DeltaTime;
    if (state.RespawnTimer <= 0f)
    {
        // 부활 처리
        state.RespawnTimer = SimulationConstants.RespawnDelay; // 3f
    }
}
```

## 3. 상수·설정값 외부화

### 3-1. SimulationConstants ScriptableObject 분리

**현재 문제:** `SimulationConstants.cs`에 밸런스 수치가 컴파일 타임 상수로 고정됨 → 수치 조정마다 재빌드 필요.

**개선안:** 밸런스 관련 값만 `SimConfig` ScriptableObject로 분리, 나머지 엔진 상수는 유지.

```
SimulationConstants.cs     ← 엔진 구조 상수 (CHUNK_SIZE, GRID_WIDTH 등)
SimBalanceConfig.asset     ← 밸런스 수치 (MoveSpeed, JumpForce, FireLifeMax 등)
```

`SimConfigSingleton`이 이미 존재하므로, 이 싱글톤에 `BlobAsset` 형태로 밸런스 값을 올리면 ECS Job에서도 접근 가능.

---

### 3-2. ArenaMatchSystem RPC 주기 상수화

**현재 문제:** RPC 전송 주기 2초가 `ArenaMatchSystem` 내부에 리터럴로 박혀 있음.

```csharp
// Before
if (elapsed % 2f < dt) { /* RPC 전송 */ }

// After
if (elapsed % SimulationConstants.MatchRpcInterval < dt) { /* RPC 전송 */ }
```

`SimulationConstants`에 `public const float MatchRpcInterval = 2f;` 추가.

---

### 3-3. WandComponents Bounce 수정자 구현

**현재 상태:** `SpellModifier.Bounce`가 열거형에 선언만 되어 있고 `SpellProjectileSystem`에서 처리 없음.

**구현 방법:**
1. `ProjectileComponent`에 `byte BounceCount` 추가
2. `BulletTerrainHitSystem`에서 충돌 시 반사 벡터 계산 (법선: 충돌면 방향 추론)
3. `BounceCount > 0`이면 소멸 대신 방향 반전 후 재진행

```csharp
// BulletTerrainHitSystem 내 Bounce 처리
if (proj.BounceCount > 0)
{
    velocity = ReflectVelocity(velocity, hitNormal);
    proj.BounceCount--;
}
else { ECB.DestroyEntity(entity); }
```

## 4. 아키텍처 정리

### 4-1. Presentation 레이어 IMGUI → UI Toolkit 전환

**현재 문제:** `ArenaHudBehaviour`가 `OnGUI()` 기반 IMGUI 사용 → 매 프레임 레이아웃 계산, 스타일 커스터마이징 어려움.

**전환 방향:**
- `UIDocument` 컴포넌트 + UXML/USS 레이아웃
- ECS 상태 읽기는 `SystemAPI.GetSingleton<ArenaMatchSingleton>()` 유지
- HUD 업데이트는 `IBindingExtensions` 또는 폴링 방식으로 ECS 값 바인딩

---

### 4-2. System 파일 분류 정리

현재 `Systems/` 하위에 40개 이상의 파일이 평탄하게 존재. 네임스페이스 + 폴더 구조 일치 강화:

```
Systems/
├── Bootstrap/        ✅ (이미 분리됨)
├── Input/            ✅
├── Movement/         ✅
├── Combat/           ✅
├── Items/            ✅
├── BattleRoyale/     ✅
├── Simulation/       ✅
└── Presentation/     ✅ — ArenaHudSystem 이쪽으로 이동 (현재 Presentation/ MonoBehaviour와 혼재)
```

`Presentation/` 폴더의 MonoBehaviour(`ArenaHudBehaviour`, `PlayerCamera`, `EntityTransformFollower`)와 ECS System(`PlayerVisualSystem`, `AnimationSystem`)이 혼재. 각각 `Presentation/MonoBehaviour/`, `Presentation/Systems/`로 분리.

---

### 4-3. Ghost 컴포넌트 정규화

`PlayerGhostData`에 직렬화되는 필드가 늘어날수록 NetCode 대역폭 증가. 필드별 `[GhostField(Quantization=...)]` 검토:

- `Position` — Quantization 1000 (밀리미터 단위)
- `Health` — Quantization 1 (정수)
- `ManaRatio` — Quantization 100 (0~1 → 0~100 정수)

불필요한 필드는 Ghost에서 제거하고 로컬 예측으로 대체.

## 5. 코드 품질

### 5-1. Magic Number 제거

코드베이스 전역에서 반복 발견되는 리터럴 수치를 상수로 교체:

| 위치 | 현재 | 교체 대상 |
|------|------|-----------|
| `PixelFireJob` | `if (life < 10)` | `SimulationConstants.FireExtinguishThreshold` |
| `PlayerMoveSystem` | `velocity.y = 14f` | `SimulationConstants.JumpForce` (이미 있으나 미사용 경우 있음) |
| `ArenaMatchSystem` | `elapsed % 2f` | `SimulationConstants.MatchRpcInterval` |
| `GroundCheckSystem` | `new int2(-1,0), new int2(0,-1), new int2(1,0)` | `GroundCheckOffsets` 상수 배열 |

---

### 5-2. 네임스페이스 일관성

일부 파일이 `using SandBlast;` 선언 없이 전역 네임스페이스에 위치. 모든 스크립트에 네임스페이스 적용:

```
SandBlast.ECS          — CA 엔진 Job/System/Singleton
SandBlast.Combat       — Wand, Projectile, Damage
SandBlast.Arena        — Match, Respawn, Countdown
SandBlast.Presentation — HUD, Camera, Animation
SandBlast.Core         — CellType, Constants, Utils
```

---

### 5-3. Job 스케줄링 의존성 명시화

현재 5단계 Job 파이프라인(Fire→Smoke→Liquid→Powder→Debris)이 `JobHandle` 체인으로 연결되어 있으나, 일부 구간에서 `Complete()` 조기 호출 의심. Burst Inspector로 각 Job의 실제 병렬화 여부 확인 후 불필요한 sync point 제거.

## 6. 테스트 인프라

### 6-1. 픽셀 시뮬레이션 단위 테스트

ECS Job은 `NativeArray`만 사용하므로 Play Mode 없이 테스트 가능:

```csharp
[Test]
public void FireJob_ReducesLifeEachTick()
{
    var grid = new NativeArray<byte>(/* ... */);
    grid[idx * 5 + LIFE] = 80;
    new PixelFireJob { Grid = grid }.Execute(idx);
    Assert.Less(grid[idx * 5 + LIFE], 80);
    grid.Dispose();
}
```

우선순위 높은 테스트 케이스:
- 불 수명 감소 및 소멸
- 용암 + 물 → 현무암 변환
- 화약 폭발 반경
- 독 액체 피해 누적

### 6-2. 네트워크 동기화 통합 테스트

`MultiplayerPlayModeSettings`를 활용한 2-클라이언트 자동 테스트:
- 청크 diff 적용 후 서버/클라이언트 그리드 일치 여부
- 신규 접속자의 초기 스냅샷 수신 완전성
