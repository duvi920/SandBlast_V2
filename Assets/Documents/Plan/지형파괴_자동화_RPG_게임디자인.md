# 지형 파괴 × 자동화 — 2D 횡스크롤 RPG 게임 디자인

> 작성일: 2026-05-27  
> 상태: 초안 (Draft)  
> 전제: 횡스크롤 액션 RPG 전환 계획(`횡스크롤_액션RPG_전환계획.md`) 위에 얹는 시스템 설계

---

## 0. 핵심 게임 루프

```
[탐험·전투]
    │
    ▼
[지형 발파 → 자원 수집]
    │
    ▼
[자동화 생산 라인 구축]   ←──────────────────┐
    │                                        │
    ▼                                        │
[폭탄·블록 대량 생산]                        │
    │                                        │
    ▼                                        │
[더 깊은 층 발파] ──→ [다음 티어 자원 확보] ──┘
    │
    ▼
[기술 업그레이드 → 새로운 장난감]
```

**설계 의도:** 지형을 파괴하고 건설하는 행위가 단순한 편의 기능이 아니라 **경제 엔진의 핵심 소비처**가 된다.  
폭탄과 블록의 소비량이 크기 때문에 자동화 없이는 진행이 더뎌지고, 자동화를 구성하는 재미가 게임의 중심축이 된다.

## 1. 픽셀 물리 — 재정의

### 결정: 그리드 기반 지형 + 픽셀 파티클 이펙트

현재 SandBlast의 CA(셀룰러 오토마타) 엔진을 **전면 교체하지 않고 역할 분리**한다.

| 레이어 | 방식 | 설명 |
|--------|------|------|
| **지형 (Terrain)** | 그리드 블록 | 배치·파괴 단위. Terraria 스타일 정수 좌표 블록 |
| **파괴 이펙트** | CA 픽셀 파티클 | 폭발 시 흩날리는 파편·연기·불꽃. 기존 CA 재활용 |
| **유체 특수 구간** | CA 유체 시뮬 | 용암 호수, 독 웅덩이 등 연출이 필요한 특정 구간에만 사용 |

**이유:**
- 전체 맵을 CA로 돌리면 대형 레벨(1024px 이상 수평)에서 CPU 병목 발생
- 그리드 기반으로 전환하면 청크 관리·저장·네트워크 동기화가 단순해짐
- CA의 시각적 임팩트(폭발, 잔해 흩날림)는 이펙트 레이어로도 충분히 구현 가능

### 구현 전환 방향

```
[현재]
  PixelGrid (CA 전체 시뮬레이션)
       │
  PixelGridSyncSystem → RPC 전송

[변환 후]
  TileGrid (그리드 블록 데이터)
       │
  TileGridSyncSystem → RPC 전송 (청크 단위, 훨씬 가벼움)
       │
  PixelParticleSystem (파괴 이펙트 전용, CA 재활용)
```

## 2. 지형 시스템

### 2-A. 블록 종류 (초안)

| 분류 | 블록 | 특성 |
|------|------|------|
| 자연 지형 | `DIRT` | 약함, 맨손 파괴 가능 |
| 자연 지형 | `STONE` | 기본 지형, 곡괭이 필요 |
| 자연 지형 | `BEDROCK` | 파괴 불가 (레벨 경계) |
| 광석 (T1) | `COPPER_ORE` | 얕은 층 |
| 광석 (T2) | `IRON_ORE` | 중간 층, T1 기술 필요 |
| 광석 (T3) | `CRYSTAL_ORE` | 깊은 층, T2 기술 필요 |
| 광석 (T4) | `AETHER_ORE` | 최심층, T3 기술 필요 |
| 특수 | `EXPLOSIVE_ROCK` | 충격 시 폭발, 연쇄 반응 |
| 설치 | `PLATFORM` | 올려서 통과 가능한 발판 |
| 설치 | `REINFORCED_BLOCK` | 폭발 저항 높은 건설 블록 |

### 2-B. 파괴 메커니즘

```
손 파괴   → DIRT 계열
곡괭이    → STONE, COPPER_ORE
폭발 T1   → 폭발 반경 3x3 블록
폭발 T2   → 반경 5x5 + 관통(다층 파괴)
폭발 T3   → 방향성 폭발 (수직/수평 집중)
```

## 3. 자원 시스템 — 깊이 티어 구조

### 3-A. 깊이별 티어 맵

```
지표면 ─────────────────────────────────
  0m ~ 30m   │ T1 자원 (구리, 석재)
             │ → 기본 도구·자동화 기초
─────────────────────────────────────────
 30m ~ 80m   │ T2 자원 (철, 유황)
             │ → 파괴 가능 조건: T1 폭탄 필요
─────────────────────────────────────────
 80m ~150m   │ T3 자원 (수정, 마그마석)
             │ → 파괴 가능 조건: T2 폭탄 + 내열 장비
─────────────────────────────────────────
150m ~250m   │ T4 자원 (에테르, 암흑철)
             │ → 파괴 가능 조건: T3 폭탄 + 특수 채굴기
─────────────────────────────────────────
  250m ~     │ BEDROCK (레벨 한계)
```

### 3-B. 자원 획득 흐름

1. **발파** — 폭탄으로 광석 블록 파괴 → 드롭 아이템 생성
2. **수집** — 플레이어가 직접 줍거나 **컨베이어·도르레**로 자동 수집
3. **제련** — 용광로(자동화 가능)에서 원석 → 소재로 변환
4. **소비** — 폭탄, 블록, 장비 제작에 소비

> **설계 원칙:** T1 자원만으로는 T2 구역에 진입 불가.  
> T1 자원 → T1 자동화 라인 → T1 폭탄 대량 생산 → T2 구역 발파 → T2 자원 획득.

## 4. 무기 시스템

### 4-A. 일반 무기 (내구도 기반)

```
내구도 있음 + 수리 가능 + 비교적 오래 사용
  → "아끼면서 쓰는" 주 전투 도구
  → 소모성이 아니라 투자 개념

폭탄·블록 = 소모성 + 대량 소비
  → 자동화 투자의 동기
```

| 속성 | 내용 |
|------|------|
| 내구도 | 사용할수록 감소, 0이 되면 사용 불가 |
| 수리 | 제작대에서 재료 소모 후 수리 (즉시 또는 시간 소요) |
| 강화 | T2 이상 재료로 내구 상한·공격력 업그레이드 |
| 분류 | 근접(칼·해머) / 원거리(석궁·마법봉) / 발굴(곡괭이·드릴) |

### 4-B. 무기 티어

| 티어 | 재료 | 대표 무기 | 특징 |
|------|------|-----------|------|
| T0 | 돌·나무 | 나무 검, 돌 곡괭이 | 매우 낮은 내구, 수리 불가 |
| T1 | 구리 | 구리 검, 구리 드릴 | 수리 가능, 기본 관통 |
| T2 | 철 | 철 해머, 철 석궁 | 범위 공격 추가 |
| T3 | 수정 | 수정 완드, 수정 드릴 | 마법 효과 부여 슬롯 |
| T4 | 에테르 | 에테르 검, 에테르 대포 | 지형 반응 공격 |

## 6. 이동 시스템 — 수직 진행 도구

수직 탐험을 가능하게 하는 이동 도구가 기술 진행과 함께 확장된다.

```
[T0] 사다리 (Ladder)
  └─ 벽에 설치, 한 칸씩 오르내림
  └─ 가장 느리지만 재료 최소

[T1] 로프 / 폴 (Rope / Pole)
  └─ 로프: 위로 던져 고정, 자유 이동
  └─ 폴: 수직 미끄럼, 사다리보다 빠름

[T2] 글라이더 (Glider)
  └─ 낙하 중 수평 이동 가능
  └─ 고층 이동·탈출에 활용

[T2] 훅샷 (Hookshot)
  └─ 벽·천장에 갈고리 걸어 이동
  └─ 전투 중 기동성 향상

[T3] 엘리베이터 (Elevator)
  └─ 설치형, 고정 수직 이동
  └─ 자동화 구간의 물자 수송에도 활용

[T4] 제트팩 (Jetpack)
  └─ 자유 비행, 연료 소모
  └─ 에테르 연료 필요
```

## 7. 도르레 & 컨테이너 시스템

**콘셉트:** Factorio의 컨베이어·컨테이너를 횡스크롤 수직 환경에 맞게 재해석.  
초반부터 배치할 수 있어야 자동화의 진입장벽을 낮춘다.

### 7-A. 도르레 (Pulley)

```
[도르레 고정점] ─── 로프 ─── [컨테이너 박스]
       │
  (상하 이동)
       │
  [아래 층 수집 지점]
```

- 천장/벽에 도르레 앵커 설치 → 로프로 컨테이너 연결
- 컨테이너가 지정 범위에 들어오면 드롭 아이템 자동 수집
- 여러 도르레를 연결해 수직 컨베이어 역할

### 7-B. 자동화 설비 진행

| 단계 | 설비 | 역할 |
|------|------|------|
| **T1 초반** | 도르레 + 컨테이너 | 수동 채굴 자원 자동 수집 |
| **T1 중반** | 컨베이어 벨트 | 수평 자원 이동 |
| **T1 후반** | 기초 용광로 | 수동 제련 → 반자동 |
| **T2 초반** | 자동 채굴기 | 특정 블록 자동 파괴·수집 |
| **T2 중반** | 자동 폭탄 투하기 | 설정 좌표에 폭탄 자동 투하 |
| **T2 후반** | 분류기 (Sorter) | 자원 종류별 자동 분류 |
| **T3 초반** | 자동 조립기 | 폭탄·블록 자동 제작 |
| **T3 중반** | 파이프라인 | 유체(용암·물) 자원 이송 |
| **T4** | 에테르 동력 라인 | 설비 전체에 에너지 공급 |

### 7-C. Factorio 스타일 배치 UI

- 설비는 **그리드 스냅** 방식으로 배치
- 입력·출력 슬롯 방향 지정 가능 (위/아래/좌/우)
- 로프/파이프/벨트로 연결
- 연결 시 자원 자동 흐름 시작

## 8. 경제 균형 설계

### 소비 vs 생산 구조

```
[소비처]                     [생산처]
────────────────────────     ─────────────────────
폭탄 1개 = T1 자원 15개  ←  자동 채굴기 1대 = 분당 8개
블록 1개 = T1 자원 5개       수동 채굴 = 분당 2개
무기 수리 = T1 자원 8개
용광로 연료 = T1 자원 3개/틱
```

**의도:** 폭탄 소비가 항상 생산 속도를 약간 초과하도록 설계.  
→ "지금 채굴기 몇 대 더 깔아야겠다"는 압박이 지속되어 자동화 투자 동기를 유지한다.

### 병목 지점 (재미 포인트)

| 병목 | 상황 | 해결 방법 |
|------|------|-----------|
| T1 채굴 속도 | 폭탄 재고 부족 | 채굴기 증설 or 수동 채굴 |
| 용광로 처리량 | 원석이 쌓임 | 용광로 병렬 추가 |
| 분류기 없음 | 자원이 섞임 | 분류기 설치 |
| 수직 이동 | 컨테이너 비효율 | 엘리베이터 설치 |

## 9. 기술 트리 — 단계별 해금 흐름

```
[시작]
  │
  ├─ T1 발굴 기술 ──→ 구리 폭탄 / 구리 도구 / 사다리
  │     └─ T1 자동화 ──→ 도르레 / 기초 용광로 / 컨베이어
  │
  ├─ T2 발굴 기술 ──→ 철 폭탄 / 로프 / 글라이더
  │   (조건: T1 자동화 완성 + 철 50개)
  │     └─ T2 자동화 ──→ 자동 채굴기 / 자동 투하기 / 분류기
  │
  ├─ T3 발굴 기술 ──→ 수정 폭탄 / 훅샷 / 엘리베이터
  │   (조건: T2 자동화 + 수정 30개)
  │     └─ T3 자동화 ──→ 자동 조립기 / 파이프라인
  │
  └─ T4 발굴 기술 ──→ 에테르 폭탄 / 제트팩
      (조건: T3 자동화 + 에테르 10개)
        └─ T4 자동화 ──→ 에테르 동력 라인 / 전자동 기지
```

## 10. 맵 구조

### 수직 레이어 구성

```
───────────────────────────────── 지표면 (지상)
  [숲·마을·상점·이벤트 NPC]
───────────────────────────────── -10m
  [동굴 입구층]
  구리·석재 분포, 적: 슬라임·박쥐
───────────────────────────────── -30m
  [T1 주 채굴 구간]
  채굴기·도르레 배치 공간, 넓은 공동(空洞)
───────────────────────────────── -80m
  [T2 전이 구간]
  철·유황, 좁은 수로(독 액체), 적: 광석 골렘
───────────────────────────────── -150m
  [T3 수정 동굴]
  수정 군집, 마그마 웅덩이, 적: 수정 드래곤
───────────────────────────────── -250m
  [T4 심층부]
  에테르·암흑철, 극한 환경(내열 장비 필수)
  적: 최종 보스급 몬스터
─────────────────────────────────  BEDROCK
```

### 가로 확장

- 각 층은 **수평으로 무한 탐험 가능** (청크 생성 방식)
- 같은 깊이에서 바이옴이 다를 수 있음 (얼음 동굴 / 용암 동굴 / 독 늪 등)
- 지상 기지 → 수직 엘리베이터 → 각 층의 채굴 기지로 연결되는 구조

## 11. 기존 SandBlast 시스템과의 연계

| 기존 시스템 | 활용 방향 |
|-------------|-----------|
| CA 픽셀 엔진 (Fire/Smoke/Liquid/Powder) | 폭발 이펙트 파티클 전용으로 축소 |
| `PixelImpactUtility` (폭발 반경 처리) | 그리드 블록 파괴 로직으로 재작성 |
| `WandCastSystem` / `SpellData` | T3~T4 마법 무기로 재활용 |
| 플레이어 이동 (점프·대시·충돌) | 그대로 유지 |
| `MapTemplate` ScriptableObject | `LevelDefinition`으로 확장 (적 배치 + 광석 분포) |
| `ArenaMapBuilder` | `CaveGenerator`로 교체 (프로시저럴 동굴 생성) |
| SPUM 캐릭터 애니메이션 | 그대로 유지 |

## 12. 기술 리스크 및 대응

| 리스크 | 심각도 | 대응 |
|--------|--------|------|
| CA → 그리드 전환 시 기존 픽셀 물리 재작성 비용 | 높음 | `TileGrid`를 신규 구현하고 CA는 파티클 전용으로 분리 유지 |
| 자동화 설비 상호작용 복잡도 증가 | 중간 | T1 설비부터 단계적 구현, 초반엔 도르레·컨베이어만 |
| 프로시저럴 동굴 생성 + 광석 배치 | 중간 | 퍼린 노이즈 기반 단순 구현 → 이후 바이옴별 규칙 추가 |
| 자원 균형 튜닝 (소비·생산 속도) | 중간 | `SimBalanceConfig` ScriptableObject에 전부 외부화 |
| 대형 맵에서 자동화 설비 엔티티 수 급증 | 낮음 | 카메라 밖 설비는 틱 간격 늘리는 LOD 시스템 적용 |

## 13. 구현 우선순위

| 순위 | 항목 | 이유 |
|------|------|------|
| 1 | 그리드 블록 지형 시스템 (`TileGrid`) | 모든 시스템의 기반 |
| 2 | 기본 폭탄 (3×3 파괴) + 블록 설치 | 핵심 행위 루프 |
| 3 | 도르레 + 컨테이너 (T1 자동화) | 자동화 진입장벽 최소화 |
| 4 | 깊이별 자원 생성 (T1~T2) | 진행 동기 부여 |
| 5 | 사다리 → 로프 이동 시스템 | 수직 탐험 가능하게 |
| 6 | 컨베이어 벨트 + 용광로 | 자동화 확장 |
| 7 | 점착 폭탄 + 관통 폭탄 (T2) | 장난감 추가 |
| 8 | 자동 채굴기 (T2 자동화) | 자동화 핵심 |
| 9 | T3~T4 자원·도구 | 후반 콘텐츠 |
| 10 | 엘리베이터 + 제트팩 | 이동 풀 완성 |
